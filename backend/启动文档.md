# Backend 启动文档

## 快速启动

### 开发模式（本地开发）
```bash
npm run dev
```
- 自动监听文件变化并重启
- 适合本地开发调试

### 生产模式（服务器部署）
```bash
npm start
```
- 正常运行，不自动重启
- 适合生产环境

---

## 完整部署流程

### 1. 首次部署

```bash
# 克隆代码
cd /path/to/backend

# 安装依赖
npm install

# 配置环境变量（首次需要）
cp .env.example .env
nano .env  # 编辑配置

# 运行数据库迁移（如果有数据库）
npm run db:migrate

# 启动服务
npm start
```

### 2. 环境变量配置

编辑 `.env` 文件：

```bash
# 数据库配置
DATABASE_URL=postgresql://user:password@localhost:5432/dbname

# 服务器配置
PORT=8080
HOST=0.0.0.0
NODE_ENV=production

# 日志级别
LOG_LEVEL=info

# Playwright 配置（可选）
RESOLVER_PLAYWRIGHT_ENABLED=true
RESOLVER_LOCAL_CHROME_PROFILE_DIR=/path/to/chrome/profile  # 可选

# 其他配置
# ...
```

### 3. 使用 PM2 后台运行（推荐）

```bash
# 安装 PM2（全局）
npm install -g pm2

# 启动服务
pm2 start src/index.js --name nexa-backend

# 设置开机自启
pm2 startup
pm2 save
```

### PM2 管理（生产环境）
```bash

pm2 logs nexa-backend

pm2 logs nexa-backend --lines 200

pm2 delete nexa-backend

pm2 show nexa-backend

pm2 monit
```

```bash

# 后台运行（nohup）
nohup node src/index.js > output.log 2>&1 &

# 查看进程
ps aux | grep node

# 停止进程
kill <PID>
```

## 故障排查

### 服务无法启动

1. **检查端口占用**
```bash
# 查看 8080 端口占用
lsof -i :8080
# 或
netstat -tulpn | grep 8080

# 杀掉占用进程
kill -9 <PID>
```

2. **检查环境变量**
```bash
# 确保 .env 文件存在
ls -la .env

# 查看环境变量是否正确
cat .env
```

3. **检查依赖**
```bash
# 重新安装依赖
rm -rf node_modules package-lock.json
npm install
```

### PM2 相关问题

```bash
# 重置 PM2
pm2 kill
pm2 start src/index.js --name nexa-backend

# 查看错误日志
pm2 logs nexa-backend --err

# 查看详细信息
pm2 show nexa-backend
```

### Playwright 相关问题

```bash
# 重新安装 Playwright 浏览器
npx playwright install chromium

# 安装系统依赖（Ubuntu）
sudo npx playwright install-deps chromium
```

### 数据库连接问题

```bash
# 测试数据库连接
psql -h localhost -U your_user -d your_database

# 检查数据库是否运行
sudo systemctl status postgresql
```

## 性能优化

### PM2 集群模式
```bash
# 使用所有 CPU 核心
pm2 start src/index.js -i max --name nexa-backend

# 使用指定核心数
pm2 start src/index.js -i 4 --name nexa-backend
```

### 内存限制
```bash
# 限制最大内存使用（例如 2GB）
pm2 start src/index.js --name nexa-backend --max-memory-restart 2G
```

## 日志管理

### PM2 日志
```bash
# 日志位置
~/.pm2/logs/

# 实时查看
pm2 logs nexa-backend

# 查看错误日志
pm2 logs nexa-backend --err

# 清空日志
pm2 flush

# 日志轮转（安装 pm2-logrotate）
pm2 install pm2-logrotate
```

### 自定义日志
如果需要输出到文件：
```bash
pm2 start src/index.js \
  --name nexa-backend \
  --output ./logs/out.log \
  --error ./logs/error.log
```

## 安全建议

1. **不要提交 .env 文件到 Git**
   ```bash
   # 确保 .gitignore 包含
   .env
   ```

2. **使用 PM2 的环境变量**
   ```bash
   pm2 start src/index.js --name nexa-backend --env production
   ```

3. **定期更新依赖**
   ```bash
   npm audit
   npm audit fix
   ```

4. **启用防火墙**
   ```bash
   # Ubuntu
   sudo ufw allow 8080
   sudo ufw enable
   ```

## 监控和告警

### PM2 Plus（可选）
```bash
# 注册并连接到 PM2 Plus
pm2 link <secret_key> <public_key>

# 查看在线监控
# 访问 https://app.pm2.io
```

### 简单的健康检查脚本
```bash
#!/bin/bash
# check-health.sh

RESPONSE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/health)

if [ $RESPONSE != "200" ]; then
  echo "Service is down! Restarting..."
  pm2 restart nexa-backend
fi
```

添加到 crontab：
```bash
# 每 5 分钟检查一次
*/5 * * * * /path/to/check-health.sh
```
