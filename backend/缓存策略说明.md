# 缓存策略说明

## 📊 当前缓存设置

### ✅ GitHub 解密密钥缓存

**位置**: `src/utils/megacloud-decrypt.js:63`

```javascript
keysCache = {
  data: response.data,
  expiry: Date.now() + 3600000  // 1 小时
};
```

**缓存内容**: AES-256 解密密钥（用于解密 Megacloud 数据）

**当前设置**: **1 小时**

**是否会导致视频失效？** ❌ **不会**
- 这只是解密工具，不是视频链接
- 密钥很少变化（几天甚至几周）
- 即使密钥更新，旧密钥通常仍然有效

**优化建议**: 可以安全延长

| 场景 | 建议时间 | 说明 |
|------|---------|------|
| 开发环境 | 30 分钟 | 方便测试密钥更新 |
| 生产环境 | **6-24 小时** | 减少 GitHub 请求 |
| 高可用性 | 永久 + 定期刷新 | 后台定期更新 |

---

### ❌ m3u8 视频链接缓存

**当前状态**: **没有实现** ✅ 这是正确的！

**为什么不缓存？**
1. CDN 链接包含临时 token/签名
2. 通常 **1-6 小时**后会过期
3. 过期后返回 403/404
4. 不同用户可能需要不同 token

**当前行为**:
- ✅ 每次请求都调用 `extractMegacloudSources()`
- ✅ 获取全新的 m3u8 URL
- ✅ 不会返回过期链接

## 🎯 CDN 链接有效期分析

### 典型 CDN 过期时间

| CDN 类型 | 有效期 | 判断依据 |
|---------|--------|---------|
| 短期 token | 30 分钟 - 2 小时 | URL 中包含 `exp=` 或 `timestamp=` |
| 标准签名 | 2-6 小时 | 包含签名参数 |
| 长期链接 | 12-24 小时 | 无明显过期参数 |
| 永久链接 | 不过期 | 纯 CDN 路径，无参数 |

- ⚠️ CDN 响应头: `Cache-Control: no-store, no-cache`

**推测有效期**: **1-4 小时**（需实际测试）

## 🚀 如果要实现结果缓存

### 方案 A: 保守缓存（推荐）

```javascript
const resultCache = new LRU({
  max: 500,
  ttl: 1000 * 60 * 5,  // 5 分钟
  updateAgeOnGet: false
});
```

**优点**:
- ✅ 安全，链接不太可能过期
- ✅ 仍能减少大量请求
- ✅ 错误风险低

**缺点**:
- ⚠️ 缓存命中率相对较低

**适用场景**: 生产环境，要求稳定性

---

### 方案 B: 激进缓存（需错误处理）

```javascript
const resultCache = new LRU({
  max: 1000,
  ttl: 1000 * 60 * 30,  // 30 分钟
  updateAgeOnGet: true   // 访问时刷新
});

// 必须添加错误处理
async function getVideo(url) {
  const cached = resultCache.get(url);

  if (cached) {
    // 验证链接是否仍然有效
    const valid = await quickCheck(cached.m3u8);
    if (valid) return cached;

    // 失效则删除缓存
    resultCache.delete(url);
  }

  // 重新提取
  return await extractFresh(url);
}
```

**优点**:
- ✅ 缓存命中率高
- ✅ 性能提升明显

**缺点**:
- ⚠️ 链接可能过期
- ⚠️ 需要额外的验证逻辑
- ⚠️ 增加复杂度

**适用场景**: 高流量场景，能接受偶尔失败

### 方案 C: 智能缓存（最佳但复杂）

```javascript
// 1. 短期缓存 + 后台刷新
const cache = {
  data: null,
  expiry: 0,
  refreshing: false
};

async function getVideo(url) {
  // 如果缓存有效，返回缓存
  if (cache.data && Date.now() < cache.expiry) {
    // 如果快过期（剩余 < 30%），后台刷新
    const remaining = cache.expiry - Date.now();
    const ttl = 1000 * 60 * 10; // 10 分钟
    if (remaining < ttl * 0.3 && !cache.refreshing) {
      refreshInBackground(url);
    }
    return cache.data;
  }

  // 缓存失效，同步刷新
  return await refreshSync(url);
}

async function refreshInBackground(url) {
  cache.refreshing = true;
  try {
    const result = await extractFresh(url);
    cache.data = result;
    cache.expiry = Date.now() + 1000 * 60 * 10;
  } finally {
    cache.refreshing = false;
  }
}
```

**优点**:
- ✅ 用户几乎总能命中缓存
- ✅ 链接过期前自动刷新
- ✅ 无感知更新

**缺点**:
- ⚠️ 实现复杂
- ⚠️ 需要后台任务管理
